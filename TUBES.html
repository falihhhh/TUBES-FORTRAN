Analisis Pertumbuhan Waktu Eksekusi:
  • Pertumbuhan Kuadratik O(n²): Kenaikan ukuran data 5x lipat (dari 1.000 ke 5.000) meningkatkan waktu eksekusi sekitar 27–30 kali lipat (Bubble Sort 30,1x, Selection Sort 26,9x, Insertion Sort 29,9x), konsisten dengan prediksi kuadratik 5² = 25[cite: 16].
  • Bubble Sort Paling Lambat: Pada n = 5.000, Bubble Sort membutuhkan 825,30 ms — sekitar 2,5 kali lebih lambat dari Selection Sort dan 2,3 kali lebih lambat dari Insertion Sort[cite: 16].
  • Selection vs Insertion Sort: Keduanya berada pada performa yang hampir setara; perbedaan di n = 5.000 masih berada dalam batas simpangan baku[cite: 16].

B. Pengaruh Kondisi Data pada n = 2.000 (Tabel 3)

Pengujian pada 2.000 elemen dengan tiga skenario kondisi data: terurut naik (best case), acak (average case), dan terurut terbalik (worst case)[cite: 16]:

Kondisi Data Bubble Sort (ms) Selection Sort (ms) Insertion Sort (ms)
Terurut (Best Case) 0,07 ± 0,01 48,38 ± 1,63 0,12 ± 0,01
Acak (Average Case) 113,45 ± 3,98 46,81 ± 0,78 58,49 ± 14,17
Terbalik (Worst Case) 157,24 ± 27,85 51,87 ± 2,83 89,16 ± 1,73
Analisis Pengaruh Kondisi Data:
  • Data Terurut: Bubble Sort (dengan penanda pertukaran) dan Insertion Sort selesai di bawah 0,2 ms karena berperilaku linier O(n) — lebih cepat >1.600x dan ~500x dibanding data acak[cite: 16]. Selection Sort tidak terpengaruh (48,38 ms) karena tetap memindai seluruh elemen[cite: 16].
  • Data Terbalik: Waktu Bubble Sort naik 1,4x dan Insertion Sort naik 1,5x dari kondisi acak[cite: 16]. Selection Sort menjadi yang tercepat (51,87 ms) karena jumlah pertukarannya paling sedikit[cite: 16].

2. Kesimpulan Hasil Pengujian

1

Pertumbuhan Kuadratik O(n²)

Pada data acak, waktu eksekusi ketiga algoritma tumbuh secara kuadratik[cite: 16]. Bubble Sort paling lambat (2,3–2,5x lebih lama dibanding Selection dan Insertion Sort)[cite: 16].

2

Keunggulan Linier pada Data Terurut

Pada data terurut, Bubble Sort (dengan penanda pertukaran) dan Insertion Sort berperilaku O(n) sehingga jauh lebih cepat, sedangkan Selection Sort tidak terpengaruh[cite: 16].

3

Selection Sort Unggul di Data Terbalik

Pada data terurut terbalik (worst case), Selection Sort menjadi algoritma tercepat karena meminimalkan operasi pertukaran antar-elemen[cite: 16].

4

Konsistensi dengan Analisis Teoretis

Jumlah perbandingan yang terukur konsisten dengan perkiraan teoretis, membuktikan pengukuran empiris valid untuk memverifikasi teori kompleksitas[cite: 16].
